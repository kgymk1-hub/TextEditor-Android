# アーキテクチャ

UIはJetpack Compose、本文入力はAndroidViewを介したプラットフォームEditTextです。PWAのソースコード・localStorageを直接使用しません。

- `MainActivity` / `Dialogs`：日本語UI、SAFインテント、コピー・共有、利用者の確認。
- `EditorViewModel`：タブ、リビジョン、退避ジョブ、外部保存、競合、ZIP・フォルダ・バックアップ。
- `Storage`：Roomの文書／履歴／ZIPメタデータ、DataStore設定、内部本文ファイル、WorkManager後処理。
- `NativeEditor`：日本語IME対応のネイティブ編集面、Undo/Redo、選択、記号、行操作、ハイライト。
- `TextTools`：厳密文字コード変換、改行、CSV、制限付きZIP、検索、結合、比較。
- `Previews`：WebViewの隔離、関連ファイルの仮想オリジン、Markdown、仮想スクロールCSV。

## 保存の手順

本文をUTF-8の不変ファイルとして、一時ファイル→flush→fd.sync→renameで確定し、その後Roomに参照を記録します。Roomに本文全体を毎キー入力で書きません。古い参照／欠損を起動時に検査し、履歴から復元する場合は警告と新しい編集リビジョンを付けます。孤立ファイルは24時間以上経過したものだけ整理します。

500msのデバウンス（設定可能）、タブ切替、バックグラウンド移行で退避します。外部文書の`revision`と`savedRevision`は独立しています。外部書込開始前に退避・履歴を確保し、原本のSHA-256を比較します。異なる場合は確認なしの上書きを停止します。書込後に再読込してハッシュを検証してから、書込開始時のリビジョンだけを保存済みとして記録します。

SAFの書込は提供元によって非アトミックです。作業コピーと履歴を復旧手段とし、原本への完全ロールバックやクラウド同期完了を保証しません。

## 資源とプレビュー

非表示タブに編集面を生成しません。復元時はアクティブ本文だけ読み込み、大きな非表示本文は退避リビジョンを確認してメモリから外します。本文は24MiB、ZIPは2048エントリー／展開総量64MiB／単体24MiB、異常圧縮率200倍の上限があります。本文1MiB超では128Ki文字の編集区間を用い、構文解析を停止します。HTML／Markdownプレビューは既定5MiB超で停止します。CSVはこの停止対象から外し、行オフセットを索引化して表示行だけセルに分解します。

プレビューは`https://pocket.invalid/`の仮想オリジンを使用します。HTML内の相対参照だけを、同一ZIPまたは許可済みSAFフォルダから解決します。JavaScriptは既定OFF、明示確認でその画面のみONです。INTERNET権限、JavaScriptブリッジ、WebViewのファイル／contentアクセス、外部ネットワーク、位置情報等の許可はありません。

## 編集面の選定

sora-editorは成熟したコード編集面ですがLGPL-2.1-or-laterの配布・差替え条件を含みます。初回実装ではAndroid標準EditTextを採用し、独自の保存モデルと完全に分離しました。IME・選択・クリップボード・TalkBackはプラットフォームの機構を利用し、コード支援を追加しています。20MiBの実用性能が基準を満たさない場合は、バッファ方式の改善またはライセンス条件を満たしたsora等への交換が必要です。

## 本文検索索引

Room v2にFTS4の`body_search`を追加しました。本文の不変ファイル参照と索引を同じトランザクションで更新します。日本語部分一致のために正規化した2文字トークンを使用し、検索結果は常に原文で照合します。大きい本文、索引にない本文、索引参照と保存参照が異なる本文は走査対象とします。1文字検索・正規表現も走査します。編集中のタブを索引だけで除外しません。v1→v2の移行は既存テーブルを保持し、起動時に索引を構築します。

## 大容量編集区間

`EditorWindow`でネイティブEditableのサイズを128Ki文字に制限します。編集後は区間を全文スナップショットへ差し戻し、保存モデルのリビジョンを更新します。Undoには区間位置・置換長・元の区間本文を記録し、別区間に移っても復元できます。全文保存の不変スナップショットは既存の保存・競合・バックアップ処理と共通です。全ファイルをディスク上で差分更新するバッファではないため、全体の文字列を保持するヒープは引き続き必要です。
